# 📝 Key Notes – Windows Logs

## 📖 Introduction
- **Windows Event Logs** are records generated by the Windows operating system whenever an activity occurs.
- They act as **digital records of system activity**.

---

## 📝 Quick Notes
- **Logs = digital records of system activity**  
  Every action (login, file access, network connection, errors) creates a log entry.

- **Why logs are important?**  
  They help answer key investigation questions:  
  - What happened?  
  - When?  
  - Where?  
  - Who did it?  
  - Was it successful?  
  - What was the impact?  

---

## 🧩 Basic Components of a Log Entry
- 🕒 **Timestamp** → When the event occurred  
- 💻 **Source** → System/app name  
- 📌 **Event type** → Login, error, request  
- 🌐 **Extra details** → IP address, username, user-agent  

---

# 📝 Key Notes – Log Formats

 📖 Example Syslog Message Format
A widely adopted logging protocol for system and network logs.

```bash
damianhall@WEBSRV-02:~/logs$ cat syslog.txt
May 31 12:34:56 WEBSRV-02 CRON[2342593]: (root) CMD ([ -x /etc/init.d/anacron ] && if [ ! -d /run/systemd/system ]; then /usr/sbin/invoke-rc.d anacron start >/dev/null; fi)
```
📖 Example JSON Log Format
```bash
{"time": "2023-05-31T12:34:56Z", "user": "adversary", "action": "GET", "status": 200, "ip": "34.253.159.159", "uri": "http://gitlab.swiftspend.finance:80/"}
```
📖 Example W3C Extended Log Format (ELF)
```bash
damianhall@WEBSRV-02:~/logs$ cat elf.log
#Version: 1.0
#Fields: date time c-ip c-username s-ip s-port cs-method cs-uri-stem sc-status
31-May-2023 13:55:36 34.253.159.159 adversary 34.253.127.157 80 GET /explore 200

```

📖 Example XML Log Format
```bash
<log>
  <time>2023-05-31T12:34:56Z</time>
  <user>adversary</user>
  <action>GET</action>
  <status>200</status>
  <ip>34.253.159.159</ip>
  <url>https://gitlab.swiftspend.finance/</url>
</log>

```

# 📝 Key Notes – Log Collection, Management & Centralisation

## 📥 Log Collection
- **Definition:** Gathering logs from multiple sources (servers, apps, network devices, databases) into one place for analysis.
- **Time Synchronisation (VERY IMPORTANT 🔥):**
  - Logs must have correct timestamps
  - Use **NTP (Network Time Protocol)** to sync time
  - Ensures accurate attack timeline

### ⚙️ Steps for Log Collection
1. Identify sources (server, firewall, apps)  
2. Choose log collector  
3. Configure settings (time sync, events, priority)  
4. Test collection  

---

## 🗄️ Log Management
Efficient log management ensures that every gathered log is stored securely, organised systematically, and ready for swift retrieval.  
A hybrid approach can balance storage by keeping all logs but trimming selectively.

### Key Steps
- **Storage** → Securely store logs  
- **Organisation** → Categorize logs  
- **Backup** → Prevent data loss  
- **Review** → Regular checking  

---

## 🌐 Log Centralisation
- Store all logs in one system (e.g., **Splunk**, **ELK Stack**)  
- Enables fast analysis, monitoring, and alerts  

---

## 🛠️ Practical Tool
- **rsyslog** → Collect & store logs (e.g., SSH logs to `/var/log/...`)

# 📝 Key Notes – Types of Logs

## 📂 Application Logs
- Messages from specific applications
- Provide insights into status, errors, warnings, and operational details

## 📂 Audit Logs
- Record events, actions, and changes within a system or application
- Provide a history of user activities and system behavior

## 📂 Security Logs
- Capture security‑related events such as:
  - Logins
  - Permission alterations
  - Activities impacting system security

## 📂 Server Logs
- Include system logs, event logs, error logs, and access logs
- Offer distinct information about server operations

## 📂 System Logs
- Record kernel activities, system errors, boot sequences, and hardware status
- Aid in diagnosing system issues

## 📂 Network Logs
- Capture communication and activity within a network
- Include events, connections, and data transfers

## 📂 Database Logs
- Record activities within a database system
- Examples: queries performed, actions taken, updates applied

## 📂 Web Server Logs
- Track requests processed by web servers
- Include:
  - URLs
  - Source IP addresses
  - Request types
  - Response codes
  - Other request details
